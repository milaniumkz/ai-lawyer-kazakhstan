# Проверка процесса обращения AIZAN — 2026-10-05

Исправлен цикл одинаковых ответов: отдельное поле текущего сообщения больше не заменяет накопленные факты. Первое описание создаёт предварительную классификацию, последующие ответы сохраняются через существующий `/ai/classifications/{id}/clarifications`. Отвеченные вопросы удаляются из очереди; повторная классификация на каждый ответ не выполняется.

Подтверждение блокируется до заполнения уточнений; неопределённая категория требует ручного выбора. Создание дела получает `classificationId`, сохраняет выбранную категорию, факты и связь классификации с делом. Повторное создание использует стабильный ключ. Высокий риск переводит дело в `review_required`. Ручная смена категории пересчитывает необходимые вопросы.

Текст очищается после успешной отправки, остаётся при ошибке. Одновременные отправки блокируются, ошибка отображается внутри формы и не перекрывает кнопки. JSON Content-Type добавляется только при наличии тела запроса: пустой POST подтверждения теперь принимается Fastify. Перезагрузка восстанавливает диалог и текущий ответ, но не выдумывает восстановление живого микрофона. Открытие сохранённого дела загружает его UUID, факты, документы, историю и проекты; контекст предыдущего дела очищается.

Чат созданного дела вызывает существующий поиск официальных источников и настроенный AI-адаптер, а не добавляет заранее заданный ответ в клиенте. Без достаточного официального источника остаётся безопасный отказ. Проект претензии использует сохранённую сумму и доступные сведения о плательщике; повторное открытие проекта не создаёт новый документ. Метаданные вложений не выдаются за OCR или юридический анализ.

## Проверки

- 16 наборов / 86 API-тестов; lint, TypeScript и production build.
- OpenAPI, миграции, дизайн, UI/visual contracts, security, npm audit (0 уязвимостей), 7 AI-тестов, Docker compose config.
- Responsive: 25 экранов × 6 размеров, без горизонтального переполнения.
- `test:web-aizan`: телефон, текст/голос на главной, отказ микрофона, новый черновик, документы; успешные API-ответы здесь являются fixtures.
- `test:web-intake`: настоящий HTTP API. Одно первоначальное определение категории, последовательные ответы, искусственный единичный 503 и retry без дублирования, двойной submit, перезагрузка, подтверждение, дело и сохранённые факты, юридический запрос, генерация и повторное открытие дела/проекта. Только сбой 503 подменяется; успешные ответы не мокируются. Создаётся отдельный тестовый аккаунт `@example.invalid`, после теста он удаляется. Auth использует явно проверенный stub OTP.

```bash
WEB_BASE_URL=http://localhost:3016 API_TEST_ORIGIN=http://localhost:3112 CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:web-intake
```

Проверка intake добавлена в GitHub Actions после установки и публичных health checks. Локальный тест API использует in-memory repository; проверка после развёртывания обращается к настоящей серверной БД через API.

## Оставшиеся ограничения ТЗ

Предварительная классификация использует существующие детерминированные правила taxonomy; это не полноценная LLM-классификация произвольного текста. Для юридического ответа OpenAI применяется только при настроенном провайдере и подтверждённом официальном источнике. Нет автоматического файлового хранилища/OCR, утверждённых окончательных правовых выводов, автоматической отправки в государственные сервисы или подтверждения доставки. Доступны метаданные, ручная проверка и assisted mode. Эти этапы нельзя считать production-ready или называть полной реализацией ТЗ.

`npm run check` проходит серверные проверки и останавливается на отсутствующем `/Volumes/PD1000/job/flutter/bin/flutter`. Flutter этим срезом не изменялся и не проверен SDK. Совпадение дизайна 1:1 не подтверждено.
