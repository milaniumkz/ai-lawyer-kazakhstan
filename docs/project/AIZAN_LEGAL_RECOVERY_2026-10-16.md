# Legal source recovery and court stage

The chat previously stopped after the first unverified source result and only supported a pretrial claim. Confirmed facts now survive provider/composition failures. When the index fails, a primary search is unavailable, or its citations cannot be verified, the existing OpenAI adapter performs one independent internet search automatically. External sites may help discovery; only retrieved official Kazakhstan publications with matching quotes can support a ready document. The official legacy Adilet viewer is also tried on primary publisher errors, not only JavaScript shells. Available official text excerpts help the second search copy exact quotations rather than paraphrasing snippets. Authentication/configuration failures are not disguised as successful generation.

`ai.documentKind` is persisted in existing message JSON, with optional `sourceSearch` provenance. After a prepared pretrial claim, the user can select court intake in the same chat. Court intake collects court/party particulars, claim value, duty calculation or exemption, pretrial dispatch/receipt and its outcome. A new court summary needs separate confirmation. `not_sent`, `waiting`, and `fulfilled` pretrial statuses block a court draft; an unresolved dispute or a verified exception can proceed. This is a document preparation workflow: no automatic dispatch or court filing is claimed. Necessity and timing of pretrial procedure depend on the actual category, law and contract.

Ready court text is saved with title `Исковое заявление в суд` and mandatory user/expert review. The web offers pretrial dispatch preparation and court-stage choice; Flutter reads the stage and saves prepared chat content without substituting a manual template. Generation job identity includes the current draft input so an earlier pretrial job is not reused for a court draft. New Flutter actions require a signed updated binary.
