# Сверка AIZAN с техническим заданием — 7 октября 2026

Основание: приложенный `AIZAN_CODEX_HANDOFF/CODEX_TASK.txt`, 11 последних референсов, `AGENTS.md`, архитектура и критерии приёмки. Позднее требование пользователя имеет приоритет: текст, голос и общение остаются визуально на главной. Работа выполнялась в существующем проекте; отдельного демонстрационного приложения нет.

Файлы хранятся через локальный серверный адаптер, а не S3. Пути строятся из хешей идентификатора дела и содержимого; исходное имя не используется как путь. `DOCUMENT_UPLOAD_DIR` на сервере задаётся в `$APP_ROOT/data/documents`, поэтому обновление приложения не удаляет загрузки. Резервное копирование включает каталог документов. Формат/сигнатура не заменяют антивирусную проверку.

## Экраны и визуальная проверка

Все 11 экранов имеют Flutter regression-снимки в `apps/mobile/test/goldens/`: home light/dark и `aizan_02_cases`…`aizan_11_login`. Снимки получены из Flutter с реальными шрифтами и Material Icons; исходные PNG не выдаются за снимки реализации. Это эталоны текущей реализации, **не доказательство пиксельного совпадения с исходным дизайном**. Для экранов без данных снимки показывают пустое состояние и ручной путь.

- Flutter: 5 основных экранов × 6 ширин (320/360/390/430/768/1024) × 3 масштаба текста (100/130/200%); без RenderFlex overflow. Уменьшение декоративной группы логотипа не уменьшает масштаб текста пользовательских полей.
- Веб: 25 экранов × 6 viewport, включая короткий 320×568; проверка переполнений пройдена.
- Нет отдельного подтверждения на физических iOS/Android устройствах, системной клавиатуре, камере и разрешениях.

## Проверки

- API: 17 suites, 92 tests.
- Flutter 3.47.6 / Dart 3.13.5: анализатор без замечаний; 48 тестов, включая 12 regression PNG и responsive-матрицу.
- Flutter release asset bundle собран. Это не подписанный APK/AAB/IPA и не проверка платформенных плагинов на устройстве.
- Веб/admin/API: lint, typecheck, build; контракт, 10 миграций, дизайн-контракты, security scan и AI unit-тесты.
- `test:web-intake`: успешные ответы не мокируются. Только один специально вызванный 503 является тестовым. После деплоя этот же сценарий проверяет настоящую PostgreSQL.
- `test:web-aizan`: телефон, голос/текст на главной, отказ разрешения, новый черновик, вкладки и file inputs. Эти проверки используют явные API fixtures.
- Docker compose config проверен; запуск контейнеров не заявлен.

### Аудит зависимостей

Совместимые обновления устранили все high-уязвимости; `npm audit --omit=dev` возвращает **0**. Полный `npm run check` запускается, но останавливается на all-dependency audit: осталось 20 связанных moderate-отметок в dev-цепочке `argparse → sprintf-js` (GHSA-hp3w-g68c-fv3c), исправленной опубликованной версии нет. Последняя опубликованная `sprintf-js` 1.1.3 уязвима к неограниченной precision в строках формата. Это не 20 независимых ошибок продукта. Удалённый пользовательский ввод в эту CLI-цепочку не направляется.

Полный audit не отключён и не объявлен пройденным. Серверный gate использует отдельный `test:audit:runtime`, а мобильные/AI-проверки выполнены отдельно после остановки общего gate. Полный production release остаётся закрытым до устранения dev advisory и остальных пунктов приёмки.

## Неполное соответствие ТЗ / ограничения

1. Настоящие SMS/OTP и биометрические сессии требуют завершения. Staging/production проверяют серверную сессию: веб использует HttpOnly cookie, Flutter сохраняет токен в secure storage; роль определяется сервером. Подмена пользовательских/административных заголовков отклоняется. Восстановление Keychain/Keystore на физических устройствах ещё не проверено.
2. Модельный adapter реализован; без работающей настройки провайдера система использует эвристику и ручной путь. Keyword matching не объявлен полноценной AI-классификацией. Наличие настроек не доказывает успешный платный вызов.
3. Автоматический OCR, антивирус/карантин и production S3 adapter не подключены. Ручная проверка доступна. Старые документы, сохранённые только как метаданные, требуют повторной загрузки.
4. Полнота официального корпуса, применимость редакций к дате события, экспертное утверждение шаблонов и юридических выводов не подтверждены. RAG без источников отказывает безопасно.
5. Генерация сейчас выполняется через синхронный API; долговечная фоновая очередь и отмена серверной задачи по ТЗ ещё не реализованы. Мобильное восстановление черновиков/дел после перезапуска процесса не подтверждено E2E.
6. Подпись/государственная отправка/получение доставки/автоматические сроки не подключены. Assisted/manual статусы не являются подтверждением отправки или доставки.
7. Полная локализация всех состояний RU/KK/EN и точный pixel overlay всех 11 референсов ещё не приняты. Регрессионные снимки не подменяют эту приёмку.
8. Подписанные Android/iOS сборки и native → API → PostgreSQL E2E на устройствах не выполнены.

Следовательно, устранены проверенные дефекты основных сценариев и обновляется staging-сайт; полное выполнение всего ТЗ и production-ready статус не заявляются.
