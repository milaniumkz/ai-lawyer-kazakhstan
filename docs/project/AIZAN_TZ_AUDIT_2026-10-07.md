# Сверка AIZAN с техническим заданием — 7 октября 2026

Основание: приложенный `AIZAN_CODEX_HANDOFF/CODEX_TASK.txt`, 11 последних референсов, `AGENTS.md`, архитектура и критерии приёмки. Позднее требование пользователя имеет приоритет: текст, голос и общение остаются визуально на главной. Работа выполнялась в существующем проекте; отдельного демонстрационного приложения нет.

Файлы хранятся через локальный серверный адаптер, а не S3. Пути строятся из хешей идентификатора дела и содержимого; исходное имя не используется как путь. `DOCUMENT_UPLOAD_DIR` на сервере задаётся в `$APP_ROOT/data/documents`, поэтому обновление приложения не удаляет загрузки. Резервное копирование включает каталог документов. Формат/сигнатура не заменяют антивирусную проверку.

## Дополнение: функциональность без внешних интеграций

- Генерация — долговечная PostgreSQL-очередь с идемпотентностью, отменой, арендой задания и восстановлением после прекращения обработки. Запись результата и завершение задания атомарны; отменённая задача не создаёт документ.
- Правки черновика сохраняются на сервере; PDF создаётся с кириллическим/казахским шрифтом и разбивкой на страницы. Веб скачивает файл; Flutter сохраняет/экспортирует редактируемый текст.
- Flutter хранит черновик, активное дело и ID подготовки в secure storage отдельно для каждого аккаунта. Выбранное дело использует свой исходный текст; проекты и незавершённая подготовка восстанавливаются из API.
- Веб и Flutter продолжают переписку по созданному делу на главной. Для повторного HTTP-запроса используется ключ идемпотентности. PostgreSQL записывает обе реплики одним запросом; сбой подготовки ответа не оставляет одиночную реплику пользователя.
- Выход из Flutter отзывает серверные сессии и очищает текущие данные. Выбор файла привязан к исходному делу; смена дела во время выбора не запускает загрузку в другое дело. Оба сценария проверены widget-тестами.
- Календарь использует реальные задачи с подтверждённой пользователем датой и сохраняет выполнение и позволяет удалить ошибочную задачу. Выдуманные сроки/демонстрационные записи и ложные 68% готовности удалены.
- Ручная отправка сохраняет контакт и метод как черновик либо `manual_sent_unverified` после подтверждения. Это запись пользователя, не доставка.
- Поддержка сохраняет обращения, админка позволяет ответить и закрыть их; пользователь получает ответ через список своих обращений. Обзор админки считает реальные данные. Ручной импорт юридического фрагмента сохраняет черновик, не поддельную действующую норму.
- Экспорт аккаунта включает его дела, сообщения, метаданные файлов, проекты, классификации, задачи, ручные отправки и обращения. Веб скачивает JSON; Flutter предлагает системное сохранение файла.
- Полный локальный браузерный E2E проверяет перечисленные сценарии на настоящей изолированной PostgreSQL: успешные ответы не подменяются.
- `scripts/integration/check-durable-jobs.cjs` отдельно проверяет восстановление брошенной аренды после пересоздания приложения, отсутствие дублей, отмену, сохранение отредактированного проекта и ответа поддержки после перезапуска. Работает только при `APP_ENV=test`; не запускать на рабочей БД.

## Неполное соответствие ТЗ / ограничения

1. Настоящие SMS/OTP и биометрические сессии требуют завершения. Staging/production проверяют серверную сессию: веб использует HttpOnly cookie, Flutter сохраняет токен в secure storage; роль определяется сервером. Подмена пользовательских/административных заголовков отклоняется. Восстановление Keychain/Keystore на физических устройствах ещё не проверено.
2. Модельный adapter реализован; без работающей настройки провайдера система использует эвристику и ручной путь. Keyword matching не объявлен полноценной AI-классификацией. Наличие настроек не доказывает успешный платный вызов.
3. Автоматический OCR, антивирус/карантин и production S3 adapter не подключены. Ручная проверка доступна. Старые документы, сохранённые только как метаданные, требуют повторной загрузки.
4. Полнота официального корпуса, применимость редакций к дате события, экспертное утверждение шаблонов и юридических выводов не подтверждены. RAG без источников отказывает безопасно.
5. Очередь, отмена, PostgreSQL-восстановление и мобильное восстановление сериализованного черновика проверены. Перезапуск приложения с Keychain/Keystore на физическом устройстве отдельно не проверен.
6. Подпись/государственная отправка/получение доставки/автоматические сроки не подключены. Assisted/manual статусы не являются подтверждением отправки или доставки.
7. Полная локализация всех состояний RU/KK/EN и точный pixel overlay всех 11 референсов ещё не приняты. Регрессионные снимки не подменяют эту приёмку.
8. Подписанные Android/iOS сборки и native → API → PostgreSQL E2E на устройствах не выполнены.

Внешние интеграции исключены пользователем из текущей работы. Список выше описывает реально проверенную функциональность. Полная локализация, пиксельная приёмка 11 оригинальных макетов и испытания на физических устройствах остаются отдельными незавершёнными критериями; они не объявлены выполненными.
